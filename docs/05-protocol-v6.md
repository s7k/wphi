# v6 プロトコルへの WPHI の対応

v6 プロトコルは、クライアントが求めた W×H マスの地図と、その上に足した行 (移動の返事、呪文、持ち物、カバン、仲間の一覧、マップセットの 16 枠、通信の圧縮) をサーバ (phi_dm) が送る取り決め。
行の書式とサーバの判断の理由は phi_dm の `docs/dev/protocol-v6.md` (`~/workspace/phidm-v6`) にある。
この資料は WPHI がどの行をいつ送り、受けた行をどのファイルのどの関数で扱うかを書く。
行の書式は写さない。
節の名前で phi_dm の資料を指す時は「phi_dm の『地図の枠』」の様に書く。

## 1. 対応の判定と、受け持つ場所

WPHI は v6 かどうかを地図が `#v6` の行で届いたか (`Map` の `v6`) で決める。
`#ex-map view=` の返事 (`#ex-map view=W' H'` と `view=no`) はパーサが読み捨てる。
v6 に対応しないサーバ (v5y など) は `view=` を読み捨てて何も返さないので、返事を待っても `#m57` の地図が届くだけな為。

v6 でないサーバでは 7x7 の `#m57` の地図だけを描く。
以前は通った所の地形を覚えて 7x7 の外に重ねる拡張マップを持っていたが、v6 で外側の地形もサーバが送るので取りやめた。
古いサーバ向けにも残さない。
残すと地図の作り方が 2 通りになり、位置の予想 (predict.ts) と描画の両方で分岐が要る為。
起動した時に、拡張マップが localStorage に書いた地形 (`phi_automap` で始まる鍵) を App.tsx が消す。

| 場所 | 受け持つ事 |
|---|---|
| src-tauri/src/session.rs | ログインの行 (`login_lines`)、視界の要求 (`view_line`)、圧縮の展開 (`Inflate`) |
| src-tauri/src/main.rs | 地図の窓の大きさを全部のセッションへ知らせる (`set_map_view`) |
| crates/phi-proto/src/parser.rs | 行を `Event` にする |
| ui/src/App.tsx | main 窓。タブごとの状態、位置の予想と歩き方の呼び出し、呪文の列とカバンの操作 |
| ui/src/map.tsx、mapRender.ts、drawMap.ts | 地図の窓。見せる範囲、滑らせ方、描画 |
| ui/src/predict.ts、walker.ts、follow.ts | 位置の予想、スムーズ移動の歩き方、仲間について行く |

## 2. 送る行

### 2.1 ログインと世界移動

`login_lines` は `#ex-map size=57` と `#ex-map style=solid` の後に `view_line` の行を置き、最後に `#ex-switch compress=deflate` を送る。
地図の窓がまだ大きさを決めていなければ、`#ex-map view=` は送らない。

サーバは世界の移動 (ゲート) のたびに v6 の大きさとマップセットの枠の数を消す (phi_dm の『視界の要求』)。
WPHI は移動先へ `#ch-srv-ok` の後に `login_lines` を送り直すので、視界と圧縮も移動先で求め直す。
この時、セッションはパーサと `Inflate` を作り直し、最後に送った視界を北固定の物に戻す。

### 2.2 視界の要求 (`#ex-map view=`)

地図の窓は、窓に入るマス数 (4.1) を `set_map_view` で main.rs へ知らせる。
`set_map_view` は 3〜99 の奇数か確かめて `Sessions` に覚え、全部のセッションへ `#wphi-view W H` を送信キューで渡す。
この行はサーバへは送らず、セッションが受け取って覚える。
地図の窓は 1 つなので、大きさはセッションごとに持たない。

セッションは覚えた大きさを `view_line` で `#ex-map mapsets=16 view=W H` に直して送る。

- 窓より上下左右に 3 マスずつ多い (W+6)×(H+6) を求める。外周の使い方は 4.1
- 行番号と座標が 10 進 2 桁なので、外周を足して 99 を超えないように W と H を 93 で切る
- 回転 (turn) はサーバが正方形しか受け付けないので、小さい方に揃えて送る
- `mapsets=16` でマップセットを 16 枠で受ける (4.3)。知らないサーバは読み捨てる

型をセッションで揃える理由は、サーバが `#ex-map style=` を返すたびに型に合わせて送り直す為。
セッションは送受信のたびに、パーサが最後に受けた `#ex-map style=` から求めた行を、最後に送った行と比べる。
違えば送り直すので、北固定へ戻った時も W×H を求め直す。

### 2.3 移動 (`go`)

移動のキーの行は keys.ts の `moveCommand` が型 (北固定か回転か) と修飾キーで決める。
北固定は `go N` `go E` などで向きも変え、Ctrl では `go n` などで向きを変えずに進む。

北固定で 2 つの向きのキーを同時に押した斜めの 1 歩は、`stepCommands` が縦と横の 2 行にする。
縦の 1 行は `go n` / `go s` にして、横を向いたまま歩く。
縦も `go N` / `go S` で送ると、1 歩ごとに上下と左右を交互に向く為。

ログインで `#ex-switch move=diag` を送り、同じ行の返事があった接続では、北固定の斜めを `go ne` `go nw` `go se` `go sw` の 1 行で送る (#196)。
サーバは縦と横の両方のマスが通れる時だけ斜めに進め、斜めの 1 歩を平均 1.4 ティックで処理するので、縦横と同じ速さで歩ける。
スムーズ移動の斜めの 1 歩は 140ms・1 行と数える (walker.ts の `diagMs` と `diagLines`)。
返事の無いサーバには今まで通り 2 行で送る。キャラの向きは変わらない。

## 3. 受ける行の解析 (crates/phi-proto)

### 3.1 地図の行

`#v6 M` から `#v6 .` までを、パーサ (`Parser`) が 1 枚の地図に溜める。

| 行 | 関数 | 扱い |
|---|---|---|
| `#v6 M` | `parse_v6_m` | 向き、W、H を覚え、行と印の溜まりを空にする |
| `#v6 R` | `parse_v6_r` | 行番号の位置へマスを入れる。地形のバイト列なので cp932 に直さない |
| `#v6 X` | `parse_v6_x` | `x` のマスを覚え、`#v6 .` で `Cell` の `blocked` にする |
| `#v6 A` | `parse_v6_a` | マスの枠 (0 以外) を覚え、`#v6 .` で `Cell` の `set` にする |
| `#v6 O` | `parse_m57_o` | キャラを 1 人足す |
| `#ex-pos` | `dispatch_command` | 地図の `pos` にする |
| `#v6 .` | `finish_v6` | `Event::Map` を返す |

`#v6 .` の時点で H 行揃っていなければ、地図を返さない。
UI は前の地図のまま描く。
キャラは `#m57` と同じく、次の地図の最初の `O` 行で空にする。

`#v6 O` は `#m57 O` と同じ `parse_m57_o` で読み、層の位置 (`head`) と座標の桁数 (`digits`) だけを変える。
`#m57 O` は head 7、1 桁、`#v6 O` は head 6、2 桁で、向きから後ろの欄は同じ並びのまま 1 バイト後ろへずれる。
75 バイトに満たない `#v6 O` は捨てる。
巨大の印 `B` (2x2 の大きな敵) は `Chara` の `gigant` にそのまま入れ、描き方は UI が決める (4.3)。

### 3.2 型

`Map` は `width` と `height` を持ち、`#m57` では両方 7 を入れる。
`#v6` で届いた地図は `v6` が真になる。
`Cell` の `blocked` (`#v6 X`) と `set` (`#v6 A`) は、無ければ JSON に出さない。
`MAP_CELLS` (49) と `finish_map` の 7 は `#m57` の中だけで使う。

### 3.3 地図以外の行

| 行 | `Event` | UI で扱う所 |
|---|---|---|
| `#v6 G` | `Moved { dx, dy, reason }` | App.tsx から predict.ts の `onMoved` (7.2) |
| `#v6 J` | `Jumped` | App.tsx から predict.ts の `onJumped` (7.2) |
| `#v6 S` 〜 `#v6 S .` | `Spells` | App.tsx の `spells` (5) |
| `#v6 I` 〜 `#v6 I .` | `Items` | App.tsx の `items` (6) |
| `#ex-inv I` 〜 `#ex-inv .` | `Bag` | App.tsx の `bag` (6) |
| `#ex-inv no` | `BagRefused` | App.tsx の `bagMessage` (6) |
| `#v6 P` 〜 `#v6 P .` | `Party` | App.tsx の `party` と PartyPanel.tsx (10) |
| `#v6 D` | `Notice` の `mapset_define` (枠 1〜15) | App.tsx の `pendingMapsets` (4.3) |
| `#ex-eagleeye` | `EagleEye` | eagleeye.tsx (4.6) |

`#v6 I` は番号の枠へ入れ、空いた枠は `None` にする。
`#ex-inv no` を受けると、溜めていたカバンの中身を捨てる。
一覧の行は、終わりの行が来ないまま増え続けないように `MAX_LIST_LINES` で切る。

### 3.4 テスト

出力比較テスト (`tools/golden/gen.py` と `tests/golden/parser.json`) は、phi-client-web の Python 版のパーサを正解にしている。
Python 版は v6 を知らないので、v6 の行は parser.rs の単体テストで確かめる。
正解データは Python 版の `size` のまま残し、tests/golden.rs が比べる前に `width` と `height` に分ける (`split_size`)。
正解データを書き換えると、Python 版が正解である事が崩れる為。

## 4. 地図の画面 (ui)

### 4.1 要求する大きさ

地図の窓 (map.tsx) は地図の欄の幅と高さをマスの大きさで割って、W と H を決める。
マスの大きさは 32px (`CHIP_SIZE`) に倍率 (4.5) を掛けた物で、高さからは上にはみ出すチップの分 (`MAP_TOP`) を引く。
クラシックは欄に入るマス数を奇数へ切り下げ (`viewFor`)、モダンは欄を覆うマス数を奇数へ切り上げる (`viewCover`)。
モダンで地図の周りを空けない為。

送るのは、地図を出している窓だけにする。
窓の端を引きずっている間に毎フレーム送らない様に、最後に変わってから 300ms 後に `set_map_view` を呼ぶ。

届いた地図のうち窓に見せる範囲は mapRender.ts の `viewArea` が決める。

- 外周 3 マスは窓の外に置き、見せない。返事を待たずに先へ進む歩みは 3 歩までなので、その分だけ予想で地図をずらしても窓の端に `?` が出ない (#180)。スムーズ移動で地図をずらす間、窓の端に入ってくる 1 列か 1 行にこの外周の地形とキャラを描く為。外周が無いと、その 1 列か 1 行が黒いまま地図がずれる
- 位置の予想 (4.4) で地図をずらした時に `?` で埋める端も外周に入り、窓には出ない
- サーバの上限 (phi_dm の『大きさの上限』) に当たって要求より小さく届いた時も、外周は窓の外に置く。見せる範囲が窓より狭くなる
- 届いた幅か高さが 5 より小さく、外周を除くと 3 に足りない時は外周も見せる
- 窓を縮めた直後に窓より大きい地図が届いた時は、窓の大きさだけを見せる

見せる範囲は、その中の自キャラが見せる大きさで決まる位置 (4.2 の表) に来るように置く。
北固定では外周が上下左右に 3 マスずつになる。
回転は自キャラが届いた大きさ M で決まる位置にいるので、上下の外周が 1 マスずつとは限らない。
M=11 の自キャラは 7 行目、見せる 9×9 の自キャラは 5 行目なので、上に 2 行、下に 0 行を外す。

回転は N×N しか届かないので、窓が横長なら左右が、縦長なら上下が空く。

### 4.2 自キャラの位置

| 型 | 自キャラの位置 (左上を 0 とする列, 行) |
|---|---|
| solid | ((W-1)/2, (H-1)/2) |
| turn (N×N) | ((N-1)/2, N-1-⌊N/3⌋) |

turn は前が上で、後ろに ⌊N/3⌋ 行、前に N-1-⌊N/3⌋ 行が見える (phi_dm の『向きと自キャラの位置』)。
自キャラのマスは mapRender.ts の `selfPos` で上の表から決め、名前を出さないキャラ、吹き出しの基準、滑らせる時の自キャラ、マウスで進む向きの基準に使う。
マウスで進む向きを地図の中央から決めない理由は、回転の自キャラが中央より下にいる為。

7x7 の `#m57` の回転でもサーバは自キャラを (3, 4) に置く (phi_m57.rs の set_view7 の SP=2)。
なので `#m57` にも同じ表を使う。
(3, 3) とすると、回転の時に自キャラの 1 つ前のキャラの名前が出ず、自キャラの名前が出る。

### 4.3 描画

map.tsx は届いた地図に自キャラの位置 (`selfPos`) と見せる範囲 (`viewArea`) を付けて盤面にし、drawMap.ts の `drawMap` で描く。
描くマスは、見せる範囲にスムーズ移動のずらしで窓に入る列と行を足した範囲 (`drawRange`) に限る。

マスのチップシートは`Cell` の `set` (`#v6 A` の枠 1〜15) があればその枠、無ければ属性の下位 2 ビット (枠 0〜3) で選ぶ。
枠 0 は `#mapset`、それ以外は `#mapset-define` か `#v6 D` で届いたマップセットになる (map.tsx の `chipOf`)。
`#v6 A` を読まないと 5 種類目からのマップセットは枠 0 の絵になり、歩いて近い順が変わるたびに絵が入れ替わる (phi_dm の『マップセットの 16 枠』)。

マップセットの行 (`#mapset`、`#mapset-define`、`#v6 D`) は地図より先に届く。
App.tsx の `onMapEvent` はこれを地図の状態へすぐには入れず `pendingMapsets` に溜め、次の地図と一緒に地図の窓へ送る。
すぐ入れると、地図より先に届く `#v6 G` などで地図の窓へ状態を送った時に、古い地図を新しいマップセットで描く。
区域の境を越えた時に、一瞬違う道の絵になっていた。

2x2 の大きな敵 (`gigant` が `B`) は、サーバが基準マス (地図の北西の角) に 1 行だけ送り、体は地図の東、南、南東に広がる。
体の 4 マスは mapRender.ts の `charCells` が決め、回転マップでは地図の向き (`dir`) で回す。
drawMap.ts の `drawBigChara` は体の一番下の行を描く時に、巨大のフレームを体の 4 マスの大きさに広げて描く。
下の行の壁や木が体に重なる様にする為。
名前は体の一番下の行の真ん中に出す。
体のマスは、位置の予想 (predict.ts) では他のキャラのマスと同じく塞がった所に、ついて行く (follow.ts) では歩かない所にする。

サーバは `#v6 O` を 30 行で切り、自キャラに近い方から入れる (phi_dm の『キャラとオブジェ (#v6 O)』)。
広い視界では遠くのキャラから描かなくなる。

### 4.4 位置の予想

App.tsx の `predicting` が真の時だけ、predict.ts の `Predictor` で地図をずらして見せる。
条件は、表のタブで、v6 の北固定の地図で、`#ex-pos` が届くか `#v6 G` を送るサーバである事。

`#v6 G` を送らないサーバでは、`go` を送った後に地図も「進めません」も来なければ、進んだとみなして最後の地図をずらす。
サーバは見え方が変わらないと、進んでも地図を送らない為。
待つ時間は、最近の返事の時間の最長に 30ms を足した長さ (120〜1000ms)。
送った移動と届いた地図は、地図の位置 (`#ex-pos`) の差で照らし合わせる。
行き先が鍵の掛かった箱 (`%`) か扉 (`{`) なら、進んだとみなさない。
サーバは音だけ鳴らして行を何も送らないので、進んだとみなすと箱の上に乗って見える為。

`#v6 G` を送るサーバでは、返事で進んだかを確定する (7.2)。

地図のずらしは predict.ts の `predictedMap` が行い、新しく入る端の 1 行か 1 列を `?` で埋める。

### 4.5 倍率とモダン

窓の形の既定はモダン (settings.rs の `modern`) で、`modern` の無い古い settings.json もモダンで開く。

マップの倍率は 100%、200%、300% のどれか (settings.ts の `MAP_ZOOMS`) で、v6 の地図と v6 でない 7x7 の地図で別に持つ。
map.tsx は倍率を画面の実際のピクセル (devicePixelRatio) で整数倍に揃える。
半端な倍率ではドットの幅が揃わず、名前の文字が崩れる為。
表示倍率 150% で設定が 100% なら、画面のピクセルで 2 倍 (CSS の px で 1.33 倍) にする。

モダンは窓を覆うマス数をそのまま求める。
外周を足して 99 を超える時 (4K の窓を 100% で見る時など) だけ、倍率を 1 段ずつ上げて収める。

### 4.6 イーグルアイ

v6 の接続ではサーバがイーグルアイを m57 の区域の外で 65x49 で送る (phi_dm の『イーグルアイ』)。
パーサ (parser.rs の `EagleEyeAccum`) は幅を行の頭から、高さを届いた行番号の最大 + 1 から決め、書式の 2 桁で書ける 99x99 まで受ける。
サーバは `#ex-eagleeye pos` を送らないので、自キャラの位置 (`self`) は盤面の中央 (幅/2, 高さ/2) にする。

EagleEye の窓 (eagleeye.tsx) は 1 マス 32px で canvas に描き、CSS の `object-fit: contain` で縦横比を保ったまま窓いっぱいに合わせる。
窓の既定の大きさは、65x49 が 1 マス 16px で入る 1040x784。

## 5. 呪文の列 (`#v6 S`)

`#v6 S` は覚えている呪文を、`cast` で選ぶ番号の順に送る (phi_dm の『呪文 (#v6 S)』)。
WPHI はこれを魔法の列 (SpellBar.tsx) にアイコンで並べる。
アイコンは効果 (`ef`) ごとのドット絵、背景の色は属性 (`fn`) で決める。

唱えた呪文はサーバの一覧の先頭へ移り、番号が入れ替わる。
列の並びは spells.ts の `orderSpells` がキャラごとに最初に見た順で固定し、番号だけを今の物にする。
並びは localStorage の `wphi-spell-order:<タブの名前>` に保存する。
ドラッグか Shift+← / → で並べ替えると、`moveSpell` で並びを書き直す。

唱える時は `cast` と今の番号を 2 行で送る (`castLines`)。
名前で唱えると、phi.td の `:U MT` の無い世界では詠唱時間が掛からない為。
`cast` の一覧は出さない。
先頭以外を唱えた後は番号が入れ替わるので、次の `#v6 S` が届くまで (最長 5 秒) 列を押させない (`waitsForOrder`、`spellWaiting`)。

Alt+1〜8 と F1〜F7 は、魔法の列の左から何番目かを唱える (keys.ts の `spellSlot`、App.tsx の `castSpellSlot`)。
サーバの番号ではなく列の位置で選ぶ。
サーバの番号で送ると、唱えるたびに番号が入れ替わり、列と違う呪文になる為。
`#v6 S` を送らないサーバでは列が無いので、所持魔法の n 番を `cast` で唱える。

## 6. カバン (`#v6 I` と `#ex-inv`)

手持ちの 8 個 (`#v6 I`) とカバン (`#ex-inv`、どこでも出し入れ出来る預かり所) を、BagPanel.tsx に並べる。
中身の欄と断る理由は phi_dm の『呪文・持ち物・カバン』にある。

カバンは E キーか行動のメニューの「カバンを開く」で開く。
App.tsx の `openBag` はパーティの窓を閉じてカバンを開き、`#ex-inv list` を送る。
カバンの操作は App.tsx の `sendBag` で送る。
`sendBag` は前の操作でサーバが断った理由 (`bagMessage`) を消す。
`#ex-inv no` の理由は `BAG_REFUSED` の文にしてカバンの見出しの下に出す。
まとめて送った途中の 1 行をサーバが断っても、後に届く一覧では理由を消さない。

| 操作 | 送る行 |
|---|---|
| 手持ちを入れる | `#ex-inv put 枠` |
| 手持ちへ出す | `#ex-inv get 番号` |
| 足元へ置く | `#ex-inv drop 番号 個数` |
| 使う、装備する | `#ex-inv use 番号`、`#ex-inv equip 番号` |
| 捨てる | `#ex-inv destroy 番号 個数`。確かめてから送る |
| 店の買い取りへ全部渡す | `#ex-inv offer`。確かめてから送る (App.tsx の `offer`) |
| 足元の物を全部拾う (メニューの `bag-pick`) | `#ex-inv pick` |
| 装備中以外の手持ちを全部入れる (メニューの `bag-stash`) | `#ex-inv put 枠` を枠の後ろから |
| 装備を外す | `unequip` と番号。一覧は出さない |

カバンの番号はサーバの並び (名前の順、同じ名前は入れた順) で 1 から数える。
1 つ出すとそれより後ろの番号が 1 つずつ詰まる。
なので選択モードでチェックを付けた物をまとめて置く、出す、捨てる時は、番号の大きい順に送る。
手持ちを全部入れる時に枠の後ろから送るのも、同じ理由による。
カバンの中身が届き直すと番号がずれるので、BagPanel.tsx は選択モードのチェックと選んでいた物を外す。
外さないと、詰まった後の別の物を置いたり捨てたりする。

並べ方 (名前、種類、属性、攻撃力、重さ) は ui/src/bagSort.ts の `SORTS` で、見せる順だけを変え、送る番号は変えない。
選んだ並べ方は localStorage の `wphi:bagSort` に覚える。

足元の物は `#ex-inv floor` で求め、`#ex-inv F 番号<TAB>欄` 〜 `#ex-inv F .` で受ける (#189)。
欄は `#v6 I` と同じで、お金は `gp=` だけになる。番号は `get` の一覧と `#ex-inv pick` と同じ数え方。
古いサーバは知らない行に断りを返すので、最初はカバンの窓の「足元を見る」を押した時だけ求める。
一度受けた後は、カバンの出し入れの度に続けて `#ex-inv floor` を送って取り直す。
「手持ちへ」は `get` と番号を続けて送り、一覧は出さない。

## 7. 通信の圧縮と移動の返事

### 7.1 圧縮

ログインの行の最後に `#ex-switch compress=deflate` を送る (phi_dm の『通信の圧縮』)。
対応していないサーバは読み捨てて何も返さず、圧縮しないまま届く。

受けたバイト列は、行に分ける前に session.rs の `Inflate` に通す。
`Inflate` は `\n#ex-switch compress=deflate\n` を探し、その後ろを zlib 形式として展開する。
返事の行が 2 回の受信に跨っても見つけるように、前に受けた分の末尾を残しておく。
世界移動で移動元の `#trs-ok` を待つ間 (`wait_line`) も、同じ `Inflate` を通す。
圧縮の終わり (StreamEnd) の後ろにバイトが届いたら、壊れた流れとして接続を切る。
`WPHI_RECORD` に書くのは展開した後のバイト列にする。

### 7.2 移動の返事

`#v6 G` を一度でも受けると、predict.ts の `Predictor` は返事で移動を確かめる作りに変わる (`confirms`)。

- 返事の来ていない移動は、押した向きのまま列に持つ。`onMoved` で一番古い移動を確定する
- 見せる位置は、`#v6 G` で確かめた位置から、残りの向きを今の地図でなぞり直して出す (`replay`)。前の 1 歩の予想が外れても、後の 1 歩は本当の位置から決まる
- 地図は `#v6 G` の後に届く。地図が来たら確定した分を消す。地図の位置の差で照らし合わせる処理は使わない
- 「進めません」は `#v6 G 0 0` と重なるので数えない
- 1.5 秒待っても返事の来ない移動は捨てる。移動先の選択の最中の `go` は番号としてサーバが読み、返事が来ない為
- 返事を待ちきった移動を進んだとみなす処理は残す。回線が遅い時に、返事より先に動いて見せる為
- 鍵の掛かった所への 1 歩も、動かない 1 歩として列に残す。抜くと `#v6 G 0 0` と順番が合わなくなる

`#v6 G` の語は `onMoved` が次の様に扱う。

| 語 | 扱い |
|---|---|
| `wall` `lock` `edge`、語の無い古いサーバ | 通れる見た目のマスなら、サーバが断ったマスとして覚える (9 の `refused`) |
| `chr` `obj` `bind` `palsy` `busy` | 覚えない (`PASSING`)。相手が動くか、自分の状態が治れば通れる為 |
| `push` | 押した後の地図が来るまで位置を進めない。地図が 500ms 来なければ進める |

`push` で待つ理由は、押す前の古い地図をずらすと、オブジェが自分のマスに重なって見え、地図が来て前へ跳ぶ為。

`#v6 J` (go 以外で動いた) を受けると、`onJumped` が epoch を変え、覚えた `passed` `refused` `tunnel` (9) を捨て、滑らせずに次の地図を描く。
`#v6 X` の印のあるマス (`Cell` の `blocked`) は、見た目が道でも通れないとみなす。
見た目が道のバリアーや、浅い水に見える通れない水に当たる前に止める為。

盲目 (`#cond` の 7 文字目) の間は、自分以外のマスが `/` で届くので、`/` を通れるか分からない所とする (`setBlind`)。

## 8. スムーズ移動の描き方

設定の画面の「スムーズ移動」(`smoothMove`、既定でオン) は、北固定の時に、自分が歩いた分だけ地図を前の位置から滑らせて描く。

自分の位置は、`#v6 G` を送るサーバでは predict.ts の `walk` (1 マスずつ歩いた分の合計に、進んだとみなした分を足した物) を使う。
`walk` は `#v6 G` を受けた時点で変わるので、地図が届くのを待たずに滑らせ始める。
`#ex-pos` だけが届く世界では、地図の位置 (`map.pos`) を使う。
テレポートで 1 マスより大きく飛んだ時、タブを切り替えた時、接続し直した時は `walk` の `epoch` を変え、滑らせずに描く。

`#v6 G` を送るサーバでは、main 窓が付けた 1 歩の始まりの時刻 (`walk.at`) と時間 (`walk.ms`) を時刻つきの経路に足す (mapRender.ts の `timedWalk`)。
地図の窓は今より `SLIDE_DELAY_MS` (30ms) 前の時刻の位置を描く。
前の 1 歩の残りはそのまま描き、続けて次の 1 歩を描くので、状態が届くのが 30ms 以内の遅れなら止まらずに一定の速さで滑る。
それより遅れて届いた 1 歩と、外れを直す 1 歩は、今描いている位置から残りを滑らせる。

`#ex-pos` だけが届く世界では、受けた位置と時刻を並べ、少し前の時刻の位置を前後の位置の間を直線で補って描く (`walkAt`)。
遅らせる時間は 130ms を下限に、続けて歩いている間の最近の間隔に合わせて延ばし、250ms を上限にする (`walkDelay`)。
止まっていた後の 1 歩目は、その 100ms 前まで前の位置にいた事にして 100ms で滑らせる (`addWalk`)。

どちらも、位置を受けた時刻から滑らせ始める作りにしない。
main 窓から地図の窓へ状態が届くまでの時間が 7〜26ms 揺れるので、届くのが遅れると前の 1 歩を滑り終えて止まり、長押しで歩くとガタガタに見える為。

滑らせる間は、地図を毎フレーム描き直さない。
周りに 2 マス広く描いた地図 (自キャラ以外) を 1 回だけ別の canvas に描き、毎フレームはそれをずらして写して自キャラを描く (map.tsx の `paint`)。
毎フレーム 900 ほどのチップを描くと、WebKitGTK では 1 回が 16ms を超えてフレームが落ちる為。
滑らせる間に `MapView` を React で描き直さない事と、地図の中身の比較 (JSON) を地図が変わった時だけにする事も、同じ理由による。

地図は自キャラより後ろの行と前の行の 2 枚に分け、後ろ、自キャラ、前の順に重ねる。
止まっている時は上の行から順にチップとキャラを重ねるので、自キャラの 1 つ下の行の壁 (上へ 16px はみ出す) が自キャラの足元に重なる。
滑らせる間も同じ重なりにする為、自キャラの絵より完全に下にある最初の行から前の 1 枚に描く。
上下に滑らせる間はこの行が滑らせる量で変わるので、変わった時に 2 枚を描き直す。

## 9. スムーズ移動の歩き方

`#v6 G` を送るサーバで、スムーズ移動が有効な北固定の時は、WPHI の側で 1 歩ずつ歩く (ui/src/walker.ts の `Walker`)。

### 9.1 1 歩の拍

- キーを押した時に、返事を待たずに 1 歩を送って進んだとみなし (predict.ts の `walkStep`)、地図をその位置まで滑らせる
- 1 歩を滑りきるまで次の 1 歩を始めない。縦横の 1 歩は 100ms、斜めの 1 歩 (2 行) は 200ms。サーバは 0.1 秒に 1 行ずつ処理するので、これより短くするとサーバより先へ進む
- 押し続ける間の 1 歩は、前の 1 歩の終わる予定の時刻から始める。20ms ごとの見回りの遅れを次へ持ち越さない為。予定の時刻より後に離したキーは、その時刻にはまだ押していたので、その 1 歩も出す
- この拍で、押した時間 T に対する歩数を、見回りのタイミングに依らず `floor(T/100)+1` にする (walker.test.ts で確かめている)。予定の時刻から 40ms より遅れた時 (返事待ちで止まった、離して押し直した) は、今から数え直す
- 返事 (`#v6 G`) の来ていない行が 3 つ (`MAX_UNCONFIRMED`) あれば、次の 1 歩を待つ。斜めは 2 行と数える。返事は「往復 + サーバのティック待ち (0〜100ms)」で届くので、3 つなら往復 100ms まで止まらない (walker.test.ts のサーバの模型で確かめている)

設定の「歩き出し」(`smoothWeight`、-2 軽い〜0 標準〜2 重い、既定 0) は、キーで歩く時の押し始めの重さ (walker.ts の `WEIGHTS`)。
押し始めの 1 歩の時間を最高速の 1 歩 (0.1 秒) の何倍かにし、押し続けた時間に比例して 1 倍へ戻す。

| 段 | 押し始めの 1 歩 | 1 倍へ戻るまで |
|---|---|---|
| -2 | 0.5 倍 | 0.3 秒 |
| -1 | 0.75 倍 | 0.3 秒 |
| 0 | 1 倍 | すぐ |
| 1 | 1.75 倍 | 0.3 秒 |
| 2 | 2.5 倍 | 0.5 秒 |

押し続けた時の速さは、サーバが 0.1 秒に 1 行しか処理しないので、どの段も同じ。
軽い段は、短い 1 歩が返事待ちで止まるまで先へ進む。
押している向きのキーが無い所から押した時に最初からにし、押したまま別の向きを足しても続ける。
追尾移動とついて行くには掛けない。

### 9.2 キーの押し離し

- キーのリピートは使わず、押している間かどうかを keydown と keyup だけで決める。OS のキーリピートは最後に押したキーにしか掛からないので、時間で離したとみなすと、上を押したまま右を押して離した時に止まる
- 窓のフォーカスが外れた時は keyup が届かないので、全部離したとみなす (map 窓は `RELEASE_ALL` を送る)。map 窓は keyup も main 窓へ送る
- 2 つの向きのキーを同時に押すと斜めに歩く。2 行を続けて送り (2.3)、地図は斜めに 1 回で滑らせる。逆向きは打ち消す
- 片方の向きだけが通れない地形なら、もう片方だけを縦横の 1 歩として送り、壁に沿って滑らせる (predict.ts の `pick`)
- リスト (ゲートの行き先など) が出たら歩くのをやめ、押していたキーは離したとみなす。閉じた後は、押したままのキーリピートでは歩き出さず、押し直すまで待つ (App.tsx の `walkHalted`)。サーバは行き先の選択の最中に届いた行を番号として読み、番号でなければ選択をやめる為 (phi_dm/input.rs の `ST_TRANSSELECT`)。押し続けた `go` がゲートを素通りさせていた
- リストより先に送ってしまった `go` (返事の往復が 1 歩の 100ms より遅い時) は WPHI の側では取り消せない
- 追尾移動も同じ歩き方にする。地図が 30ms ごとに送る向きが 120ms 届かなければ止まる
- 歩いた 1 歩 (`walk 8 100ms`) と、返事を待って止まった時 (`walk wait unconfirmed=2`) をトレースに書く

### 9.3 通れない所への 1 歩

- 地図の文字で通れないと分かるマス (predict.ts の `BLOCKED`) への 1 歩は、進んだとみなさず、その場で 4px 寄って戻る揺れ (120ms) を見せる (map.tsx の `BUMP_PX`)。岩 `@`、木 `T`、檻 `I`、窓 `|`、ガラス `=`、鍵の掛かった箱 `%` と扉 `{`、壁 `#` `H` で、サーバが `T_CWALL` の印で止める地形 (phi_dm/view.rs の `move_chr`) のうち地図の文字で分かる物
- `go` はサーバへ送り、当たり判定はサーバが決める。壁と同じ文字で届く隠し扉をサーバが通した時は、`#v6 G` で届いた分だけ位置を直す
- 見えない所 `?`、地図の外、他のキャラやオブジェの居るマスへの 1 歩は、通れるか分からないので、進んだとも止まったともみなさない。揺らさずにその場で返事を待ち、返事が来るまで次の 1 歩を送らない (`uncertain`)。サーバが通せばそこへ滑らせ、断れば揺らす
- 壁の文字のマスへ止めた 1 歩をサーバが通したら、そのマスを walk の座標で覚え、以後は揺らさずに進む (`passed`)。通した直後は、同じ向きに続く壁の文字のマスも通れるとみなして進む (`tunnel`)。`#v6 G 0 0` が 1 度返るか、壁でないマスへ進んだらやめる。覚えるのは自分が通ったマスだけで、まだ見つけていない隠し通路は見せない
- 通れる見た目でサーバが断ったマスは walk の座標で覚え、次からは進まずに揺らす (`refused`)。透明な壁の前で押し続けた時に、進んでは戻るのを繰り返さない為。1 歩は送り続けるので、サーバが通したら (居た物が退いた、麻痺が解けた) 忘れる
- それ以外で進めなかった 1 歩 (深い水と浅い水が同じ `_` で届く水など) は、`#v6 G 0 0` が届いた時に、なぞり直した位置へ 80ms で滑らせる (引き戻し)
- `passed` `refused` `tunnel` は epoch が変わる (テレポート、`#v6 J`、タブの切り替え、接続し直し) と忘れる

## 10. 仲間の一覧 (`#v6 P`)

サーバは仲間の一覧 (Party eye と同じ情報に HP、MP、状態異常を足した物) を、変わった時に送る (phi_dm の『仲間の一覧 (#v6 P)』)。

- 受けた一覧は、パーティに入っている間だけ右上に小さく出し、押すと窓を開く (ui/src/PartyPanel.tsx)。パーティを抜けたら、パーティのタブから全体へ戻す
- 地図ですぐ隣のキャラを左クリックすると、誘うメニューを出す。`join` は向いている先の相手しか誘えないので、`turn` でその向きを向いてから送る。回転マップでは画面の上が前なので、`turn l` `turn r` `turn b` を使う
- 隣のキャラのマスは塞がっていて歩けないので、左クリックをメニューに使っても歩く操作は減らない

### 10.1 仲間について行く

仲間の窓の「ついて行く」か、地図で隣の仲間を左クリックしたメニューの「ついて行く」で、その仲間の隣まで歩き続ける (ui/src/follow.ts)。
サーバへは何も足さず、`go` を送るだけ。

- 仲間の位置は、地図に見えていればそのキャラの位置、見えていなければ `#v6 P` の dx と dy (同じ階の時だけ届く)
- 道は、見えている地図 (位置の予想でずらした物) の通れるマスを幅優先で探す。通れない地形、サーバの通れない印 (`#v6 X`)、見えない所 `?`、2x2 の大きな敵の体は歩かない。仲間の隣 (縦横 1 マス) に着いたら止まり、仲間が動けばまた歩く
- 仲間が地図の外なら、仲間に一番近づけるマスへ向かう。今より近づけなければ止まって待つ
- 1 歩は、スムーズ移動ならその歩き方 (追尾移動と同じく walker の `setFollow`)、そうでなければ前の移動の返事を待って 0.11 秒に 1 歩まで
- 仲間の位置が一度に 3 マスより大きく動いたら、ゲートやスイッチで飛んだとみなし、仲間が最後に立っていたマスの上へ乗る。踏むと飛ぶ所なら自分も飛び、着いた先から仲間を探し直す (自分が飛ぶと predict.ts の epoch が変わる)
- 行き先を選ぶゲートの一覧が出たら、やめて「ゲートで移動しました。行き先を選んでください」と出す。仲間がどれを選んだかはクライアントから分からない為
- 3 秒見失ったら (別の世界へ移った、階が違う)、やめて知らせる。パーティから外れた時もやめる
- 裏のタブのキャラもついて行く (複数のキャラを 1 つの WPHI で動かす時)。位置の予想は表のタブの分しか無いので、裏のタブは最後に届いた地図から次の 1 歩を決める。1 歩送ったら、地図 (進めなかった時は移動の返事) が届くまで次を送らない (最大 0.6 秒待つ)。ゲートで飛んだかの判断は表のタブだけ
- 移動のキー、Esc、上の帯の「やめる」でやめる
- 移動の返事 (`#v6 G`) を送る v6 のサーバで、北固定の地図の時だけ使える。歩いた位置を `#v6 G` で確かめる (predict.ts の `walk`) 為

## 11. 戦闘の行 (`#v6 E`・`#v6 W`・`#v6 H`)

どれもサーバの仕様は phi_dm の docs/dev/protocol-v6.md にある。WPHI の受け方だけを書く。

| 行 | WPHI がする事 |
|---|---|
| `#v6 E 種類 AX AY TX TY 属性 分類 [待ち]` | 地図の座標の位置に演出を出す (map.tsx の fxEls)。座標から窓に見せている範囲の左上を引く。続くログの行の増減の数字も、その位置に出す。届くサーバでは、名前で探す斬撃と魔法弾は出さない |
| `#v6 W cast=<ティック> <呪文>` / `cast=stop` | 唱えている人の頭の上に詠唱バー。自分の詠唱の間は、ついて行く・追尾移動・自動攻撃の `go` と `hit` を待たせる (DM は詠唱中に行を受けると詠唱を止める為) |
| `#v6 W at=<ティック>` | 自キャラの足元の攻撃の待ちの輪が、長さで縮んで消える |
| `#v6 H C<番号> hp=<0-100> ag=<0|1>` | 減っているキャラ・対象・狙っている敵の頭の上に HP バー。視界から外れたキャラ (`#v6 O` に載らない) の値は捨てる |

| `#v6 B 番号<TAB>gp=値段<TAB>欄` 〜 `#v6 B .` | 乗ったマスの売り場の品を店の窓に出す (ShopTalk.tsx)。「買う」は確かめてから `pay 値段` を送る。品は売り場のスイッチが出すので、拾うのは利用者。空の一覧 (`#v6 B .` だけ) で窓を閉じる (#187) |
| `#v6 K 言葉[<TAB>menu]` 〜 `#v6 K .` | 地図のキャラのメニューの「話す」で、相手の方を向いて `#ex-talk` を送り、届いた言葉を会話の窓のボタンに並べる。押すと NPC の言葉は `言葉?`、メニューの選択はそのまま送り、続けて `#ex-talk` で言葉を求め直す。空なら知らせて閉じる (#188) |
| `#v6 T 種類 [C<番号>]` | 次の 1 行の発言の種類。ログの絞り込み (全部・発言・戦闘) で、スイッチの案内 (switch) を発言から外し、NPC の台詞 (npc) を発言に入れる (#190) |

| `#v6 L 名前<TAB>dx=<TAB>dy=` 〜 `#v6 L .` | GM が置いた自分の階の目印。視界の外なら地図の端に黄色の矢印と名前と距離、視界の中ならその場所に旗を出す (北固定の時だけ。#191) |
| `#v6 Y ask` / `with` 〜 `.` / `done` / `end 理由`、`#ex-trade no 理由` | 取引 (#192)。地図のキャラのメニューの「取引する」で `#ex-trade C<番号>` を送る。申し込まれたら確かめて `#ex-trade ok` か `cancel`。一覧が届くと取引の窓を開き、手持ちとカバンの物 (`put 枠` / `bag 番号`)、お金 (`gp 額`)、承諾 (`ok`)、やめる (`cancel`。Esc も) を送る。`done` か `end` で閉じる |
| `#v6 Q 番号<TAB>kind=<TAB>title=<TAB>text=` 〜 `#v6 Q .` | 今出ている依頼と今の段階の目的を、モダンの右上に本筋 (main)・日課 (daily)・寄り道 (sub) の順に出す。寄り道は最後に替わった 1 件だけを出し、残りは「他 N 件」で開く。kind が無ければ sub (#193) |

`#end-mg` は、呪文の一覧を出していなければ mode が変わらないので、パーサは詠唱の終わりとして `castEnd` を必ず送る。

## 12. 決めていない事

- サーバが phi_dm.cnf で上限を下げた世界では、モダンでも地図の周りが空く。倍率を上げて埋めるかを決めていない
- 回転の時に窓が横長だと、N×N の地図の左右が空く (4.1)。7x7 の回転と同じ扱いでよいかを決めていない
